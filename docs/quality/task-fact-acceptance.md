# 任务事实与发送审计：验收设计

2026-10-11 设计稿（未实现，已经过一轮对抗审查修正）。配套[产品](../product/task-facts.md)与[技术设计](../architecture/execution-seams.md)。风格沿用 [Q6](limited-memory-acceptance.md)/[G3](../status/memory-cross-device-sync.md)：案例分载体执行并留记录；未执行前标未执行，不改名已通过。

## 案例矩阵（TF 系列，24 例）

**A 沉淀正确性（A1-A5，storage 单测 + 集成）**
- A1 终态→事实：任务到 completed，一条 task_fact 落库且正文含结果状态与日期；进行中/待确认任务不产生事实；`task_fact_index` 建立映射。
- A2 两阶段崩溃闭合：执行事务提交（execution.db v2 的 pending 登记与终态同事务）但事实写入前杀进程 → 重启对账补写；对账幂等（跑两遍仍一条）。
- A3 重做=新行：同 fingerprint 新任务终态 → 旧行置墓碑（**不清聊天**）、新 memory_id 新行、映射改指新行；旧 id 本地与服务端墓碑都保留。
- A4 删除后重做：用户删除事实（墓碑+精准清+映射清除）→ 任务重做落全新 id，服务端接受（不触 resurrection），不复活旧 id。
- A5 未知态如实：回执丢失 → 事实记"结果未知"；核对完成后更新。

**B 用户控制与不可伪造（B1-B6，browser + native）**
- B1 面板分区：任务事实区与手动记忆分开显示，来源标注"来自电脑上的文档任务"；无创建/编辑入口。
- B2 可删除：删除走确认弹窗并触发精准清（用户动作保留确认门）。
- B3 注入受控：默认不注入；勾选后发送边界行显示"任务事实 N 条"；与手动记忆共用 5 条/800 字预算。
- B4 不可伪造：模型回复声称完成不产生事实；mock 模型声明完成 → 面板无新条目。
- B5 上限隔离与驱逐不清聊天：50 条满时挤最旧（仅置墓碑）；**被驱逐事实引用过的轮次不被删除**；手动记忆 30 条与条目不受影响（分列后旧 30 校验对手动记忆仍生效——重构回归钉）。
- B6 手机不可更正：peer-update 携带 kind=task_fact → 服务端 400/409 拒绝；手机删除 task_fact 正常（走既有墓碑路径）。

**C 发送审计（C1-C7，storage 单测 + native）**
- C1 每次成功发送可重建：行含记忆块全文/system 版本/个人块摘要/轮次区间/条数字数；按重建规则拼出与实际一致的模型输入（**断言与捕获的请求体逐段相等**，非仅存在性）。
- C2 失败请求也入账：取消、超时、epoch 失配丢弃的请求各留一行且状态标注——这些请求没有轮次行，证明审计独立生命周期。
- C3 日常逐出不清审计：6 轮全局逐出删最老轮次后，对应时间的审计行仍在；精准清同理。
- C4 空态可失败：无记忆/无个人块时行存在且各段为显式空标记——**反向断言**：损坏 logger（全写字段）必须被 C1 的逐段相等逮住（mutation 验证，防空断言）。
- C5 不额外发送：负测请求体不含审计字段。
- C6 手机侧删除的级联不入审计语义：手机删除记忆 → 桌面 pull 应用（tombstone_and_prune）→ 审计行不受影响（审计记发送事实，不记同步事件）。
- C7 边界：语音链请求不入账（负测一行）；"全部删除聊天"清空审计表。

**D 跨端（D1-D3，coordinator/桌面集成复用）**
- D1 task_fact 同步：桌面沉淀 → 手机可见可删；手机删除 → 桌面墓碑。
- D2 旧桌面跳过物化：task_fact 快照/事件到达旧桌面 → 镜像但不物化、不复活（复用 skipped_kind 断言模式）。
- D3 分列容量的跨端一致性：手动 30 + task_fact 40 的账号，手机新建手动记忆成功（服务端分列容量）；桌面 push task_fact 第 51 条被拒且**不 drop 循环**（capacity 在分列语义下可重试或挤旧后再推，行为按实现钉住）。

**E 提醒（E1-E2，native）**
- E1 到点提示：设置提醒 → 到点桌宠侧提示；重启恢复；取消即删；仅用户经 UI 创建（无模型调用路径）。
- E2 不虚报：不产生系统通知、不产生任务事实。

**F 执行器缝回归（F1-F2，集成）**
- F1 迁移等价：指名重跑 `apps/desktop/src-tauri/src/account/tests.rs` 的 `desktop_mobile_same_companion_integration`（真 RemoteDocuments 循环 + 真 coordinator fixture + 手机浏览器链）——迁移后全绿且至少一例在迁移前故意破坏可失败（防空转）。
- F2 契约校验：Artifact 哈希缺失/状态越界 → 拒绝且不产生事实。

## 门槛与边界

- 载体分工与 G3 相同；实现顺序：§0 承重变更 + §1 管线（A/B 组）→ §4 审计（C 组）→ §2/§3 缝（F 组，无行为变化）→ 提醒（E 组）。
- 全部通过不宣称 T16/T17 全包、G3 或商业可售；新 scope 选型仍以真实设备联合验收与用户任务证据为准。
