# 真实设备联合验收单（跨端体验第 1 项）

> 2026-10-06。跨端五步路线第 1 项的执行清单：在真实电脑与真实手机上人工走完登录、六位码配对、文档确认与取消、断网与中断恢复、进度与记录管理、个人记忆注入。本单是执行要求而非结果声明；逐项填写文末结果表后才构成验收记录。运行指南见[配对](../development/device-pairing.md)、[文档协作](../development/remote-documents.md)、[手机联调](../development/mobile-web.md)、[个人记忆](../development/personal-memory.md)；能力边界以各[交付记录](../status/development-progress.md)为准。

## 准入（先记录，再动手）

在仓库根目录打开三（或四）个终端：

```powershell
npm run coordinator     # 终端一：协调服务（保留既有账号库，不要删除）
npm run mobile:https    # 终端二：手机网页 + 临时 HTTPS 隧道（以控制台最新输出链接为准）
npm run desktop         # 终端三：桌面；或先 npm run build:desktop 再运行 release exe
npm run memory:serve    # 终端四：个人记忆服务（仅 D 组场景需要）
```

- 各终端必须是同一 commit 的代码；旧进程先正常退出再启动。Quick Tunnel 重启可能换链接。
- SMTP 与受邀邮箱沿用本机配置，真实收取 8 位验证码；同邮箱两次申请验证码需间隔至少 60 秒（冷却真实生效）。
- 桌面聊天需已配置可用模型，D 组发送才会产生回执。

开始前记录：日期、执行人、commit、桌面构建方式（dev 或 release exe）、电脑系统与版本、手机型号/系统/浏览器、两端网络（同一 WiFi、不同网络或蜂窝）。

## A 登录与配对

### A1 双端登录同一账号

1. 电脑：角色气泡 → 任务面板 → 账号与共享待办，邮箱验证码登录（已登录可跳过）。
2. 距上次申请验证码至少 60 秒后，手机打开隧道链接，同邮箱申请验证码并登录。
3. 手机新建一条待办并随后取消。

预期：两端显示同一账号与伙伴标识；电脑约 10 秒内（或点刷新）看到该待办及取消；共享待办互通不依赖配对。

### A2 六位码配对与撤销

1. 电脑「设备配对与权限」填写电脑名称，生成五分钟配对码（保留前导零）。
2. 手机「连接电脑」输入六位码（手输一次、复制带空格粘贴一次），填手机名称，核对电脑名称、标识与权限说明后确认。
3. （可选，谨慎）故意输错一次：应得到明确失败提示。**不要连续错五次**——账号级五分钟失败窗口真实生效，会锁住核对与确认。
4. 两端刷新配对列表。
5. 从手机撤销关系，电脑刷新。

预期：双端显示同一配对关系且本端角色正确（电脑为桌面端、手机为控制端）；旧码失效不能复用；撤销后双端一致显示已撤销；配对只授予文档摘录范围，每个动作仍需单独确认。

### A3 在线状态约定超时

1. 桌面在线时查看手机配对状态行。
2. 托盘退出桌面（或断开电脑网络），观察手机。
3. 重新打开桌面并登录，观察手机。

预期：在线时显示在线、最后联系时间与可执行操作；判离线最坏约 25 秒（15 秒心跳租约 + 10 秒轮询），恢复在线最坏约 15 秒；离线期间显示“最后联系 N 秒前”。在线展示不改变每个动作仍需手机确认的规则。

## B 文档协作与恢复

### B1 全链正常路径

1. 电脑「让手机确认一份文档」选择已配对手机，选择 UTF-8 `.txt`/`.md`（最多 256 KiB），「生成本地预览」（摘录取前八个非空行、每行最多 240 字符）。
2. 核对预览后「分享预览并等待手机确认」。
3. 手机文档列表展开摘录核对，确认保存。
4. 观察手机状态推进直至完成。
5. 检查电脑 `%LOCALAPPDATA%\dev.qiban.companion\remote-documents\<协调端口>-<账号UUID>\document-drafts\<actionId>.md`。

预期：手机依次显示「等待手机确认（剩余 m:ss）」→「已确认，等待电脑保存」→「执行中（推断）」→「已保存并核验」；执行中必须带「（推断）」标注；草稿内容与确认的预览完全一致，原文件不被覆盖。

### B2 保存副本

在已结束任务点「保存副本到手机」。

预期：提示已按回报哈希核验一致；下载文件名为 `<源名去扩展>-<actionId 前 8>.md`；手机打开副本内容与预览一致。副本保存在手机本地，与电脑文件互不影响。

### B3 取消路径

1. 再分享一份，在「等待手机确认」时手机点「取消或请求停止」。
2. 再分享一份，确认后在「已确认，等待电脑保存」时取消。
3. （可选）在「执行中（推断）」时请求停止。

预期：尚未准入的显示「已取消」，电脑不执行、不产生文件；已进入保存过程的显示「已请求停止，等待电脑核对」，结果以电脑回执为准——可能回报已保存成功，如实显示，不保证即时回滚。

### B4 电脑断网与恢复（不重复执行）

1. 分享并确认一份，随即断开电脑网络（动作从分享起五分钟有效）。
2. 观察手机状态与提示。
3. 有效期内恢复网络，等待执行。

预期：手机显示电脑离线及最后联系时间，并说明需在有效期内联网执行、过期自动取消；恢复后执行一次、只生成一个文件。若拖过有效期显示自动取消、电脑不执行，同样是正确结果。

### B5 进程中断与结果未知

1. 分享并确认一份，在「执行中（推断）」阶段用任务管理器强制结束桌面进程。
2. 观察手机；重开桌面（登录会话凭据仍在）。

预期：手机显示「已开始，电脑离线」或「结果未知」类状态及恢复指引；重开后自动核对并补回执，状态澄清为已保存或未保存；document-drafts 中该任务只有一个文件，不重复生成。

### B6 退出/重开与会话语义

1. 托盘退出桌面再重开。
2. 电脑退出登录，重新登录同一邮箱。

预期：仅退出重开（会话仍有效）时配对与在途任务恢复处理；退出登录后旧配对失效，重新登录不继承、需重新配对；已保存的本机草稿文件保留。

## C 进度与记录管理

### C1 手机断网与刷新核对

文档进行中断开手机网络几秒再恢复。

预期：断网时显示服务不可达提示并保留旧数据，不谎报状态；恢复后自动刷新；各状态有对应刷新与核对入口；服务不可达、电脑离线、结果未知三者文案可区分。

### C2 已结束记录删除

1. 完成至少一条记录后，在「已结束的任务」段点「删除记录」，阅读确认弹窗后确认。
2. 刷新列表。
3. （可选）手机断网时点删除，观察失败提示；恢复网络后再删。

预期：确认文案讲清四要素——从手机与服务端消失且无法撤销、电脑不再执行或补报、已保存的草稿文件与已开始的写入不受影响；删除后行消失且刷新不回，配额释放（可再分享验证）；断网删除显示失败提示、恢复后行仍在、重删成功；结果未知的记录不可删，提示需电脑核对结束后清理。

### C3 删除后的重新分享

1. 对已执行完的同一份本地任务，在电脑再次点分享。
2. 重新选择同一文件生成新预览，走完整链路。

预期：旧任务重分享被明确拒绝（“该摘录已执行完毕，本地不会再次执行；请重新选择文件生成新任务”）；新任务正常确认执行——它是需手机重新确认的全新记录，不是原记录复活。

## D 个人记忆（桌面聊天）

### D1 注入与更正拒绝

1. 启动 `npm run memory:serve`；任务面板「个人记忆」区块在线显示条目。
2. 聊天策略区勾选 1–2 条（计数不超过 5 条 / 800 字）。
3. 发送一条消息，展开气泡预览与发送回执。
4. 另开终端更正一条已选记忆（id 可从面板或 `curl.exe "http://127.0.0.1:4322/v1/memories?limit=5"` 获取）：

```powershell
curl.exe -X PATCH http://127.0.0.1:4322/v1/memories/<id> -H "Content-Type: application/json" -d '{\"content\":\"验收用更新内容\"}'
```

5. 回到桌面不刷新预览直接再发送；随后刷新预览再发送。

预期：预览与回执分「应用/个人」两节；更正后用旧预览发送被拒——“个人记忆已变化或服务暂时无法核对，本次未发送，请刷新预览后重试”；刷新后按新内容发送成功。

### D2 离线行为（可选）

1. 预览前停止 memory:serve，发送一条消息。
2. 在线预览后停止服务，再发送。
3. 重启服务。

预期：预览时即离线，明示后可发送、本次不含个人记忆、回执如实记录；在线预览后掉线则拒绝发送；离线可移除勾选或关闭注入，新增勾选被拒；服务恢复后面板可重新连接。

## 已知边界（如实）

- 本单在本机联调环境执行：Quick Tunnel 临时 HTTPS，页面与 API 流量经过 Cloudflare；不构成正式部署准出。
- 一次通过不等于浏览器兼容矩阵准出；iOS Safari、微信内浏览器等另行验证。
- OTP 冷却、配对失败预算、文档/配对配额都是真实限制，测试时按文中上限操作。
- 桌面本地台账与已落盘文件不随记录删除清理，桌面端暂无删除 UI（[记录清理边界](../status/document-cleanup.md)）。
- 他处已删后重删得到“已不存在”文案的竞态已由集成测试覆盖，本单不要求手工复现。
- 语音全链、角色资源与性能、干净设备安装及独立用户体验不在本单，见[首次使用验收单](first-use-acceptance.md)与路线第 5 项。
