# 桌面 AI 伙伴：质量测量与试用运行协议

> v1.1｜2026-09-13｜配套[执行计划](../planning/agile-stage-gate-plan.md)与[待办](../planning/delivery-backlog.md)。本文为待实现、待冻结的方法，不包含已通过测试或真实用户结果。主计划定义阶段决策，本文定义采集与计算；冲突先修订，不能择宽执行。

## 1. 测量基线和记录

QA在G1登记设备CPU/GPU/内存、Windows/WebView2/驱动、显示器与缩放、角色资产、构建、模型、语音服务、端点设置、测试数据版本、日期和执行者。参考机加两台边界设备共三台，至少覆盖双屏100/150%混合缩放。具体型号尚未提供，不标记支持矩阵已完成。

候选网络条件：N1正常组在实测供应商链路上要求往返延迟P95≤100ms、抖动≤20ms、丢包≤0.1%；N2在同一链路额外注入双向合计200ms延迟、±50ms抖动及1%丢包，记录实际值。若当地真实网络无法达到N1，G1改服务地区/供应商/承诺并在正式测试前冻结基线，不能测试后改分组。网络条件只用于复现，不宣称覆盖所有客户网络。

T46交付测试工具：Windows进程与图形事件采集脚本、前端交互/播放时间标记、音频回放与回环录制、服务端关联日志、网络故障注入适配、任务故障夹具、汇总脚本。具体Windows测量适配应在G1样机中确定，未选定或无法运行时相应Q项缺证据，不能用代码中的“已播放”事件代替真实可听音频。开发工作已列T46，共4～6工程人日；若实测超出，按剩余工作重估。

原始数据位置约定为 `evidence/<build>/<Q-ID>/<run-id>/`（执行时创建，当前没有此目录中的测试结果）。每条记录至少含：case_id、设备/网络/音频组、构建与配置哈希、开始/结束单调时钟、请求/任务/动作ID、预期结果、实际结果、失败/取消/超时类别、关联费用、执行者和复核者。不同机器的单调时钟不直接相减，跨端延迟优先在手机同一时钟采起止；跨设备追踪只用于分段诊断。

## 2. 统计与复核规则

- 预先冻结用例集、随机种子/顺序、超时值和分组；预热单列，不进入正式样本，也不在看到慢结果后重测替换。
- P50/P95采用nearest-rank：排序后取第ceil(p×n)项；不做插值。正常发起但失败/超时、无语义音频的样本在延迟排序中计为正无穷，另报告有限延迟分布和成功率。不能只报告成功请求的P95。计划内取消独立组统计，不混入响应成功率；非计划断连不剔除。
- 语音正常组语义响应成功率候选≥98%，超时15秒；弱网30秒，按降级提示/可取消是否符合预期验收。正常/弱网及耳机/扬声器分别报告，不合并掩盖差异。分母包含服务拒绝、失败、超时及重试前的原始轮次；重试费用另计，不能把重试算新增成功用户。
- Q5正常成功率按每类工具分别计算，至少30例时≥95%意味着至少29例成功；越权、不可解释重复副作用、虚假完成任一出现即阻断，不靠平均分抵消。
- 对测量工具本身使用已知时间序列、慢样本、失败/超时夹具核对分位数与分母；原始结果不可覆盖。修复后的回归另生成run-id，保留失败记录。
- 超时或卡顿提示只证明可理解的降级，不等同完整能力成功。所有人工挑选的案例标明选择方式，Q7制作质量与真实用户购买理由分表。

## 3. Q1～Q10测量矩阵

下表的人时是一次完整覆盖的QA计划值，含准备和复核，开发接入/修复计入相应T事项。自动运行时间是机器占用，允许并行但必须提前预约。样本量用于工程覆盖，不能推导总体零风险。

| ID／用例前缀 | 采集与通过规则 | 自动化与人工边界 | QA人时／机器占用估计 |
|---|---|---|---|
| Q1 WIN | 3台×关键流程各5轮；安装/升级/卸载、窗口、收起、混合缩放、休眠恢复；按主计划全过 | 安装/启动脚本辅助；焦点、穿透、拔屏人工检查 | 8h／约4h，可并行 |
| Q2 RES | 每5秒采进程树CPU、private bytes和GPU引擎占用；参考机24h，另两机各8h；CPU按全机100%口径、内存按宿主及关联WebView/渲染去重求和 | 自动曲线；QA核对进程归属、休眠区间和异常 | 4h／40机时，可三机并行 |
| Q3 AVATAR | 每机100次，输入事件至首次实际呈现反馈，P95≤100ms；同时有音频和角色负载；报告帧时间与>100ms长帧 | 自动驱动与图形追踪；每机抽10次录屏逐帧复核 | 4h／约3h |
| Q4 VOICE | 2网络×2音频设备×100轮=400；用户音频实际结束至首个真正回答的可听片段；停声输入至最后可听输出，P95≤200ms；旧回答不复播 | 固定中文音频+播放回环自动批次；每组抽10轮及全部异常人工听；另每组至少5轮真人PTT检查，不替代400轮 | 10h／约8h；声音环境不可互相串扰 |
| Q5 TOOL | 三类×(30正常+发送前/执行中/回执前各10)=180；产物存在和内容标准都验，结果未知不算成功 | 类型化夹具与故障注入自动跑；草稿内容、未知状态人工抽查全部异常及每类10正常 | 6h／约4h |
| Q6 MEM | ≥50事实/更正案例、20删除同步案例；来源正确率≥95%；删除后检索、摘要和旧事件补发不得复活 | 固定对话与同步事件脚本；来源正确性由人工标注核对 | 6h／约3h |
| Q7 ROLE | 20固定情境×4维度×2复核者；均值≥4且无单项<3，差异裁决；状态矛盾必须修复 | 人工观察角色/声音/打扰，保留评分依据；非购买或心理效果指标 | QA 2h＋PO 2h／约2h |
| Q8 REMOTE | 在线≥100；断线/重连/锁屏各≥20；撤销四情形各≥20，另竞争两种顺序各10；手机点击至服务器确认接收提示同钟测量 | 自动事件/队列故障与时间采集；两种指定前台浏览器人工核心路径 | 6h／约4h |
| Q9 BOUNDARY | 固定集全过：两账号×任务/附件/记忆/账本×读/写负测至少16例；另过期、登出、撤销、目录/重解析点、恶意内容、导出删除 | 自动API/工具边界集；关键案例由非实现者复核 | 6h／约3h |
| Q10 BILL | 沙箱成功/失败/超时/重复/取消/退款；额度一致；服务回退与数据恢复至少各一轮，生产交易另核对 | 沙箱及重放自动；真实小额收退款由具备权限的人执行并人工对账 | 8h／约4h，不含支付服务开通等待 |

Q2的候选泄漏规则：剔除预登记的前30分钟预热后，按每小时内存中位数拟合趋势，斜率≤2MB/h且首末稳定窗口净增≤50MB；同时平均归属内存≤500MB。超过触发定位与返工，不能只比较开关两个点。GPU平均待机占用候选≤3%（按设备引擎分别报告）；冻结前验证工具口径。温度与功耗记录相同室温下关闭/开启伙伴的对照，商用若声称“不影响续航”必须另冻结并通过相应续航测试；当前无此承诺。摄像头/硬件热与机械测试仍归独立CG/HG门。

Q8撤销四情形为：排队后撤销、执行中撤销、离线撤销后重连、旧授权重放。按技术8.4的权威准入次序判定；在撤销前已授予的短期在途动作不能误判为新的准入，也不能隐藏其继续影响。Q8单次在线≥100为每个受支持手机浏览器组，分组报告，不将两端合并到一个P95。授权负测验证账号全部退出/设备/资源/任务各自范围。

## 4. G3前最小运行控制

以下均为小规模免费Beta的**候选配置**，不是供应商价格或已承诺套餐。PO/A在G3前依实测冻结并记录配置哈希；实际预算B0尚未确定，缺少预算不能Go。

| 维度 | 初始候选上限／行为 | 必测情形 |
|---|---|---|
| 范围 | 最多20名指定成年用户，单任务限明确工具范围 | 非名单账号无法取得试用权益 |
| 请求/语音 | 每用户每日100次模型请求、输入+输出语音合计20分钟；全局每日1,000次、200分钟；UTC+8日界固定 | 并发跨日、长语音、失败重试均计量；不能只计成功回复 |
| 费用 | 每用户每日5元、全局每日50元；滚动14日全局500元；三者与用量上限先到先停 | 使用冻结供应商价格上界预留，结算核对实际账单；未知费率能力不开启 |
| 并发 | 每用户最多1个付费模型/语音调用、1个工具动作；全局最多4个模型/语音调用和2个工具动作 | 文本+语音流水串行或排队，所有阶段纳入同一计数器，不能旁路 |
| 单任务 | 最多5个工具动作、总墙钟120秒；每次录音最多60秒、回复音频最多60秒；最大上下文/输出token按供应商配置冻结 | 接近额度任务先预留最坏费用；超时/取消后核对在途，不自动续任务 |
| 重试 | 可安全重试的瞬时错误最多2次，计入同一任务时间与费用；结果未知副作用不自动重试 | 重复回调、网络超时、停止时迟到响应 |
| 停止开关 | 云端拒绝新推理/远程动作准入，停止新增任务调度；在途按可取消边界处理 | 开关持久化、重启后仍生效；测试不能绕过；用户可见状态 |

计量在服务端原子预留，按请求/动作ID结算，队列不绕过限额。每次语音/模型调用限制输入长度、输出量和时长，确保可计算单次最大预留；供应商账单延迟或未知费用保留预留，不释放为可用额度。上限表示不再授予新调用，无法承诺取消已在途调用的所有供应商费用；G3预算须涵盖已预留在途最高费用。T45实现基础机制，T26/T27复用并扩展为套餐周期、支付权益与商业对账，避免两套计量不一致。

## 5. G3最小恢复与G4加固

T43设置定时备份及与主服务分离的备份存放，T47演练：停止测试服务并从可追溯构建恢复一次；另从备份恢复数据库/对象数据到隔离环境一次。候选恢复目标RPO≤24小时、RTO≤4小时，G3冻结并明确告知Beta可接受的数据损失范围；如产品承诺不接受此范围，先加强备份而非改写实测。

恢复演练核对固定任务、产物、记忆、删除标记、授权版本、计量和动作去重。**普通数据RPO不能用于容许复活权限或重做副作用**：恢复期间关闭调度；从独立追加的安全/动作记录核对最新状态。若无法核对，旧凭据全部失效、相关任务标未知并禁止重放、费用保守冻结待对账；删除相关数据先隔离，恢复删除清单后才能重新供检索。G3须证明该降级路径有效，不能只恢复数据库并截图。

若独立记录方案或恢复耗时超过T43/T47估算，更新实际剩余工时和G3日期；不能将尚未实现的持久性记成通过。T33在最小能力上增加签名更新、迁移兼容、灰度和用户版本恢复；收费链路在G4补生产真实核对。

## 6. QA产能与执行预约

QA 0.4FTE按每两周32小时，PO主持/角色复核另计。上述Q项一次完整覆盖共60 QA小时，需要跨轮，不承诺两周全部人工执行。如下为与28周示例对应的分配上限；非满额部分是复核和缺陷余量。计划值须由实际QA在G1确认。

| 迭代 | QA计划活动 | QA小时 |
|---|---|---:|
| S1 | 设备/方法/阈值基线与样机复核 | 16 |
| S2～S3 | 夹具定义、T46接口复核；各含PO07主持协助2h | 每轮12 |
| S4 | 自动采集试运行、已知样本核对、账号隔离预检 | 16 |
| S5 | Q1 8h、Q2 4h、Q3 4h；使用T46已交付的B端测量增量 | 16 |
| S6 | T46真实链路接入完成后：Q4 10h、Q6 6h、Q7 2h、G2复核3h、返工回归8h | 29 |
| S7～S8 | 工具/授权夹具接入和增量检查 | 每轮16 |
| S9 | Q5 6h、Q8前半3h、Q9前半3h、最小运行/恢复预检8h | 20 |
| S10 | Q8后半3h、Q9后半3h、限额与恢复最终检查8h、G3复核4h、回归8h | 26 |
| S11 | Q1～Q4按影响复核14h、Beta与Q10沙箱8h | 22 |
| S12 | Q5～Q9适用回归12h、Q10生产/恢复4h、G4复核4h、缺陷回归8h | 28 |
| S13 | 收费异常与按影响回归、恢复复演 | 20 |
| S14 | G5证据、成本复测核对及最终回归 | 24 |

Q10的完整8h基准在后期分配中覆盖；G3的最小恢复额外单列，不把Beta控制挤到收费后。机器运行与人工时间分开预约；40机时长测量可以并行，但无人值守不是零准备工时。回归只重跑受影响模块和关键交叉路径，未变化的证据必须关联同一适用构建/配置并说明复用理由。若变更使全量重跑必要，60h需要另排多轮或增加具名测试资源；不能降样本、砍负测或让门禁提前通过。
