# M4 准出评审记录

2026-10-07。对照[Q6验收设计准出条件](limited-memory-acceptance.md)（"M4只有本地集完成、关键边界全过、质量阈值达到且异常修复回归后才准出"）逐条核对三证据。评审人：用户（决策）；工程侧汇总证据并如实记录张力点。

## 条件一：本地集完成 — 满足

- 50 例发送边界 + 20 例删除竞争全部通过（2026-09-19，[本地轮记录](../status/memory-q6-local.md)，运行 `q6-20260919b`）。

## 条件二：关键边界 100% — 满足

设计要求的五条数据边界（未经确认不落库、被删正文不进新请求、失效响应不回写、跨地址/模型默认不携带、写失败不虚报成功）由本地轮 100% 通过（DEL09/10/11/12、S 组、DEL15 等），未用质量容差放过任何一条。

## 条件三：质量阈值达到 — 满足

- **50/50 来源正确**（门槛≥48）：deepseek-flash 全量轮 2026-10-07，50/50 有回答、误用 0、遗漏 0；用户逐例确认（2026-10-07T11:24:18+08:00），非模型自称或HTTP成功判据。

## 条件四：异常修复回归 — 满足

真实轮暴露两个测试驱动异常，均修复并回归：协议 v3 缺 `expectedPersonal`（`d658d13`→试验轮 5/5）；输出预算 2048 截断（`e799230`→d 轮 E04 通过）。产品侧无缺陷：截断检测、明确报错、残文不进复核的行为均正确。

## 张力点（如实记录）

1. **更正清聊天取舍**：设计规则"若更正清聊天不可接受，回到产品设计调整"。体验中用户反问"有其他更好的方式吗"，后裁定"落档，暂时不更改"。未表达不可接受，不触发回炉条件；但亦非明确接受。处置：**有条件通过**——精准清（按回执记忆使用记录只清用过该条的对话）列为待修，实现时回到本记录销项。
   - **销项（2026-10-09）**：已实现精准清——逐 scope 前缀截断（各模型对话从首个使用该条目的轮次起删除，之前的保留；删除全部与停用/移除选择同构），账本 schema v4、回执 `clearedTurns`、确认弹窗与按钮名对齐"开始新对话"。交付与验证见[精准清聊天记录](../status/memory-precise-clear.md)；v4 之前历史的回填盲区已写入产品文档 §5。
2. **单模型单轮**：deepseek-flash／DeepSeek／2026-10-07 单轮。设计要求"目标模型回归"而非服务商矩阵，字面满足；其他模型/服务商表现不因本评审推断。
3. **体验困惑 2 条**：发送内容初答未提"消息与勾选记忆发往模型服务"；删除影响范围初答不确定。按规则"记录混淆而非引导用户答正确"如实保留，列为待修（发送边界感知强化）。
   - **注记（2026-10-09）**：困惑②的弹窗侧已随精准清改进（确认弹窗按新语义描述影响范围，且回执报告实际清除轮数）；发送侧常驻边界提示与弹窗预计算轮数仍待修，跟踪于发送边界感知强化。
   - **销项（2026-10-10）**：困惑①发送侧交付常驻发送边界行（消息、轮次与已选记忆发往哪个模型服务的计数提示，离线如实标注）；困惑②补弹窗打开时接入 `chat_usage_impact` 预计算轮数（咨询值口径，真机 CDP 验证含 pet 窗 ACL 拒绝）。交付与验证见[发送边界感知记录](../status/send-boundary.md)。

**M4 准出。** 四条件全部满足；上述三条张力点不构成回炉条件，全部转为待修项跟踪。门禁由 Hold 转 Pass。
