# 任务事实：伙伴记得它替你办过的事

2026-10-11 设计稿（未实现）。对应 T16→记忆闭环与 T17 执行能力扩充的第一增量；配套[技术设计](../architecture/execution-seams.md)与[验收设计](../quality/task-fact-acceptance.md)。参考了 deepseek-harness 的三条工程不变式（见技术设计引言），不引入其插件生态。

## 解决什么问题

栖伴已经会办事（文档摘录保存草稿），但办完就忘：下次对话里问"上次那份笔记存了吗"，它只能靠聊天记录猜，或者用户自己去文档面板翻。**用户手写记忆解决"我是谁、我喜欢什么"；任务事实解决"你替我做过什么、结果如何"**——这是"伙伴"与"工具"的分界线：工具执行完就退出，伙伴记得自己经手的事。

没有这个闭环，M1 起就在记忆 schema 里预留的 `task_fact` 类型永远为空，跨端同步为它写的镜像规则也只是摆设。

## 用户看到什么

- **记忆面板新增"任务事实"区**：每条 = 一句话事实（例："10-11 替用户把《产品路线》的摘录保存为草稿，已核验"），带来源（"来自电脑上的文档任务"、任务号、时间）、结果状态（完成/失败/结果未知）。
- **只读生成，用户可控**：不可手动创建、不可编辑正文（更正 = 重做任务，事实随新结果更新）；**可删除、可停止注入**。删除走与其他记忆一致的确认流程。
- **注入默认关闭**：按模型选择启用，与手动记忆共用 5 条/800 字预算；发送边界行如实显示"任务事实 N 条"。
- **手机同步**：查看与删除经既有跨端管线；手机不可创建，**也不可更正**（任务事实正文唯一来源是执行系统——服务端路由拒绝 kind=task_fact 的更正，删除不受限）。

## 与手动记忆的边界

| | 偏好/经验（手动） | 任务事实（生成） |
|---|---|---|
| 来源 | 用户在面板填写 | 执行系统终态事件，唯一来源 |
| 创建/更正 | 用户 | 重做任务生成新事实（旧的置为已删除）；模型说"完成了"不产生事实 |
| 删除 | 用户 | 用户（触发精准清）；系统上限驱逐只置删除标记、**不清聊天** |
| 上限 | 30 条（不变） | 独立上限 50 条；满时挤掉最旧的任务事实，**永不挤用户手动记忆**（服务端与桌面按类别分列核算） |
| 内容 | 自由文本 ≤200 字 | 任务描述+结果状态+日期，≤200 字；**不含文件内容摘录**（摘录留在文档任务记录里） |

## 提醒（T18a，同批第二增量）

应用内提醒是"执行"语义的最小扩展（时间触发而非用户触发）：到点后栖栖在桌宠侧提示一句，**不虚报外部通知已发送**（不接入系统通知 API，仅应用内）；时区明确、重启后恢复、可取消。提醒历史不沉淀为任务事实（无外部副作用、无结果核验语义）。产品层一句话界定，工程挂点见技术设计。

## 诚实边界

- 任务事实只覆盖**栖伴经执行系统办过的事**：手机交办、文档摘录；闲聊里提过的事、用户自己做的事不进事实。
- 结果未知（回执丢失等）如实记"结果未知"，不猜。
- 系统驱逐（50 条上限）**不清聊天**：被驱逐事实的旧引用残留在已发历史里——历史不回改，与精准清（用户决定）语义不同。
- 事实正文明文存于本机 chat-history 与账号协调库镜像（与现有记忆一致的边界）；跨账号删除的合并语义限制沿用[跨端记忆删除同步](../status/memory-cross-device-sync.md)。
- 发送审计覆盖桌面文字链；语音轮次暂不入账（后续单独评估）。
- 不据此声称 T16/T17 全包或 G3 通过；实现与验收以[验收设计](../quality/task-fact-acceptance.md)为准。
