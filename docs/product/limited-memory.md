# T13/T14：有限记忆产品设计

版本：设计基线v0.1，2026-09-17。**本文件定义拟开发行为；当前应用尚未开放记忆管理与模型使用；底层[M1增量已实现](../status/memory-foundation.md)。** 对应[交付待办](../planning/delivery-backlog.md)T13/T14与[技术设计](../architecture/limited-memory.md)，不变更首版跨端候选范围或原人日基线。

## 1. 用户结果

共同学习或创作的用户可以让栖栖记住少量自己确认的信息，重启后不必重复说明；随时能回答“记了什么、从哪里来、发送给了谁、怎样更正或删除”。例如用户保存“讨论方案时，先给结论，再给理由”，下一次在已启用记忆的模型中交流时可使用该偏好。

当前6轮聊天记录用于接续上下文，会按容量淘汰；记忆是用户单独保存、持续保留的条目。保存聊天不自动创建记忆，清空聊天不等于清空记忆。角色不说“永远记得”“我已经记住了”，除非本次保存收到本机成功回执；模型回复不构成保存回执。

## 2. 首个增量及边界

| 信息类型 | 首个增量的写入方式 | 展示与使用规则 |
|---|---|---|
| 偏好 | 用户在“记忆”面板亲自填写并点击保存 | 如称呼、回答风格、学习习惯；标为“你填写／确认”，不是客观事实验证 |
| 共同经历 | 用户填写一段描述，可补经历日期 | 如“今天一起完成了第一份提纲”；用户叙述，不推断情感关系或把旧活动当成当前任务 |
| 任务事实 | 首个增量禁用创建，后续由具名执行器提供已校验事件 | 待办创建不等于任务完成；依赖T16的attempt/action与产物校验，不能把模型总结写成工具事实 |
| 模型猜测／自动摘要 | 不写入 | 本轮不扫描历史、不在后台抽取画像；后续候选必须有独立确认流程 |

首个增量交付手动保存、查看、编辑、单条/全部删除、JSON导出及受控文字请求注入。暂不提供聊天划词保存、导入、语义召回、相似度合并、跨端同步、语音实验注入或自动过期。自然语言“记住……”仍是普通聊天，提示用户去记忆面板保存；不扩展模型工具权限。

建议初值（容量假设，开发与试用需复核）：最多30条有效记忆，每条1～200个Unicode字符；每个模型选择最多5条、正文合计不超过800字用于交流。达到容量时拒绝新增并引导管理，不默默淘汰已确认记忆。经历日期可空；没有自动“永久有效”承诺，卡片显示最后确认时间供用户复核。

## 3. 入口与操作流程

桌宠气泡增加“记忆”入口，打开辅助面板的记忆区域；角色仍是主入口。面板卡片显示类别、正文、来源、创建/更正时间、可选经历日期、当前模型是否选用。没有条目时说明“这里只有你主动保存的内容”，不生成示例用户资料。

| 操作 | 用户看到什么 | 成功与失败 |
|---|---|---|
| 新建 | 类别、正文、经历日期；提示本机明文保存 | 点保存后才创建；成功返回卡片。失败保留草稿，不显示“记住了” |
| 查看来源 | “你在记忆面板填写／最后确认于…” | 首版没有聊天来源链接，不能伪造原始对话；后续来源不可用须明确说明 |
| 选择交流记忆 | 当前地址和模型、开关、逐条选择、条数/字数 | 默认关闭且不选任何条目；按钮“保存此模型的记忆设置”只是配置，不发起请求 |
| 编辑 | 原文、修改后的正文和影响说明 | 按“更正并开始新对话”提交，原子更新；冲突先刷新，不覆盖他人/另一窗口的新版本 |
| 删除 | 单条或全部；清楚列出同时清空的聊天范围 | 提交成功才从列表移除；失败保留原卡片并可重试；无回收站恢复内容 |
| 导出 | 原生保存对话框，导出有效卡片及来源/时间 | 用户选路径后写JSON；取消无文件，失败不报已导出，不自动上传或导入 |

聊天气泡在发送前显示“本轮将使用N条记忆”，可展开核对；关闭时显示“记忆未启用”。请求完成后显示**实际加入请求**的条目与版本，不把模型生成的“我想起了”当作调用证据。暂停/更新状态同步到两个窗口，旧状态未核对时发送按钮暂不可用。

## 4. 跨模型使用

记忆库属于这台电脑当前应用资料，不与模型绑定；使用许可按规范化API基地址＋模型编码分别保存，默认关闭。新地址或新模型不会继承许可与选择，用户须在新范围明确启用。只改输出预算不改变范围。切回旧模型保留其已保存设置，但已删除条目永不重新选中。

启用提示：“发送消息时，所选记忆会和对话一起发给此服务。”本地保存与上传是两个独立动作。首版不因供应商同品牌就复用许可；不增加网络探测或验证请求。当前语音实验不携带记忆。

## 5. 更正与删除后的旧前文

现有聊天记录可能含有已修改偏好的原话或模型复述，单删记忆卡不能阻止它再次进入前文。首版采取可检查的保守规则：**编辑/删除记忆、关闭某模型记忆或移除已选条目时，同时清空所有模型的本机聊天记录，并终止旧上下文请求的本地接收。** 在提交前明确展示这个影响，按钮名称包含“开始新对话”；用户取消则数据完全不变。

这个规则会牺牲最近6轮记录，属于首版取舍，需在体验测试中确认是否可接受。后续若引入来源依赖追踪，可缩小清理范围；不能在缺少依赖证据时声称只删了某一事实的全部副本。新建记忆、首次启用或只增加选择不清空聊天，但会使旧配置的发送快照失效。

| 操作 | 记忆条目 | 记忆使用设置 | 本机聊天 |
|---|---|---|---|
| 既有“清空对话” | 保留 | 保留 | 全部删除；提示记忆仍在，可去管理 |
| 更正一条 | 替换正文/时间、递增版本 | 保留选择该ID的关系 | 全部清空并开始新对话 |
| 删除一条 | 删除正文与来源说明，保留无正文删除标记 | 从所有选择移除 | 全部清空并开始新对话 |
| 删除全部记忆 | 全部有效条目转为无正文删除标记 | 所有模型关闭、选择清空 | 全部清空并开始新对话 |
| 停用或移除选择 | 仍可在面板查看 | 修改当前范围 | 全部清空并开始新对话 |

成功提示只承诺本地已提交、后续请求不再携带旧内容。已发出的供应商请求、用户先前导出文件、系统备份不在可撤回范围；不能承诺模型绝不自行猜出相同词句。请求/旧回复丢弃与本机清理必须真实发生，不能只改页面。

## 6. 价值验证与发布边界

内部体验应让非实现者完成“新增偏好→选择使用→重启继续→改偏好→核对新请求→删除→再重启”的完整流程。观察能否区分保存和发送、能否找到来源、是否理解更正会重开对话；记录误解、操作失败和重复说明次数，不把开发者自测推导成付费需求或留存效果。

功能门见[Q6本地验收设计](../quality/limited-memory-acceptance.md)。首个手动增量只是T13/T14本地子项；任务事实、跨端删除同步及全产品G2/G3仍按原依赖补齐。记忆设计不改变T04真实语音和T07干净设备的未通过状态。
