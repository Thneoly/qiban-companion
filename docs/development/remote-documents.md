# 手机确认与电脑保存文档摘录

2026-09-26。当前是受限文档协作验证版，配套[交付记录](../status/remote-document-confirmation.md)、[授权协议](../architecture/device-authorization.md)。

## 启动与体验

更新代码后，先在原终端停止旧协调服务和手机网关，再分别启动以下三个入口。保留现有本机配置与数据库，不需要重新填写 SMTP。已经运行的旧进程不会自动加载这次代码。

```powershell
npm run coordinator
```

```powershell
npm run mobile:https
```

```powershell
npm run desktop
```

也可运行最新构建的 `target/release/companion-desktop.exe`。手机访问本次 HTTPS 入口；Quick Tunnel 重启可能换网址。

1. 电脑从伙伴气泡打开「任务面板」→「账号与共享待办」，电脑和手机使用同一邮箱登录。
2. 依[配对指南](device-pairing.md)完成手机与电脑配对。重开且会话有效时可恢复；退出或重新登录后需要重新配对。
3. 电脑在「让手机确认一份文档」选择手机，再选择 UTF-8 `.txt` / `.md`（最多 256 KiB），点击「生成本地预览」。此时摘录只在电脑本地，尚未上传。
4. 核对摘录，点击「分享预览并等待手机确认」。仅文件名和显示的摘录上传账号服务。完整源文件不上传；摘录本身可能包含敏感文字，请按显示内容决定是否分享。
5. 手机展开这份文档的摘录，点击「确认电脑保存这份摘录」并确认。动作从分享起最多五分钟有效，手机确认不会延长期限；电脑应用与协调服务需保持运行。
6. 电脑获取单次准入、再查授权，创建新的 Markdown 草稿并校验内容哈希。手机刷新显示「已保存并核验」。两端前台约五秒刷新；有未结束任务时电脑后台也会轮询，关闭面板不等于取消任务。
7. 手机可点击「取消或请求停止」，或撤销配对。尚未准入会取消；已经进入保存过程时，结果必须等待电脑核对，不能保证即时回滚。已保存的文件不会因撤销而删除。

浏览器 `npm run dev` 仅作界面预览，不提供实际桌面文档执行。当前摘录取前八个非空行、每行最多 240 字符，并附固定说明；没有调用模型，也不是语义摘要。

## 结果和恢复

- 草稿位于桌面应用数据目录 `remote-documents/<协调端口>-<账号UUID>/document-drafts/<actionId>.md`。在 Windows 通常位于 `%LOCALAPPDATA%/dev.qiban.companion/` 下，具体以 Tauri 应用数据目录为准。不会覆盖原文件。
- 「已保存并核验」表示电脑已核对实际草稿与确认预览一致并上报。手机可在已结束的任务里「保存副本到手机」：手机端先对预览做哈希比对回报的产物哈希，通过才保存，副本内容与电脑文件一致且相互独立。
- 准入响应丢失时先核对授权和本地台账。无法证明本次可开始执行时不写入，可能显示「未保存成功」。需要时重新生成一份预览再确认。
- 草稿已落盘而回执丢失，电脑重开或下次轮询会核对产物并补回执，不创建第二份文件。无法核对的结果保留「结果未知」。
- 重开恢复要求原登录会话仍有效。新登录不会继承旧配对或旧会话文档列表；已保存本机文件保留。手机在线不意味着电脑在线，页面不承诺离线电脑已执行。

## 数据与版本

协调服务 schema 3 → 4，保留账号、伙伴、待办、配对及旧动作，增加文件名和摘录表。旧版程序会拒绝新版数据库，不可手改版本号降级。新本地台账与原「文档任务」相互隔离，普通本机入口无法执行手机待确认的任务。

每账号最多 20 条共享文档、500 条动作（已结束记录可从手机删除并释放配额，见[记录清理](../status/document-cleanup.md)；unknown 与在途状态需等待结束）；每个电脑账号目录最多 100 条本地文档任务，包括尚未分享的预览，本地台账与文件不随服务端删除清理、无清理入口。文件名、摘录和本地执行记录以明文存储，退出仅撤销会话，不删除记录。

## 自动验证

`npm run test:desktop-account` 使用独立测试数据库、内存测试邮箱和临时 Windows 凭据，验证原生 Rust 执行与手机页面；不调用真实 SMTP 或模型。`npm run test:browser` 覆盖桌面选择文件、预览后显式分享、退出后清理界面，账号 IPC 为测试替身。真实 Tauri 窗口与用户手机联合验收仍需人工进行。
