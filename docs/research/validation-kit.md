# AI 伙伴需求验证工作包

> 可执行的研究材料；尚未招募参与者或收集数据。重点验证净协调负担、未满足的交流需要与形态适配，不预设融合产品必然成立。

配套材料：[协调情境离线原型](../../prototypes/companion-validation/index.html) · [原型主持说明与数据口径](simulation-protocol.md)。原型使用预写模拟，仅用于材料预试和协调交互探索，不能替代本工作包的真实事件记录或伙伴持续价值研究。

## 1. 先写清要作什么决定

本轮结束只决定：是否存在重复、值得进一步服务的情境，以及下一轮优先测试协调、陪伴、融合还是其他价值。不决定市场规模，不宣布长期心理效果，不直接批准完整平台开发。

| 编号 | 待验证假设 | 可观察证据 | 当前状态 |
|---|---|---|---|
| A1 | 使用多个 AI 或同时推进多个任务，留下现有工具未解决的协调负担 | 事件、时间、遗漏、纠错及已有应对方式 | 待测 |
| A2 | 统一协调方式比优化后的现有流程更省力，且保持质量与掌控 | 对照任务结果、总用时、恢复时间、理解和错误 | 待测 |
| B1 | 某些人的交流和支持需要在独立活动中未得到满足 | 最近实例、当时想要的支持、现有替代及实际满意度 | 待测 |
| B2 | 稳定伙伴参与活动产生可持续的额外价值 | 重复自愿选择、具体体验、非使用时反馈和退出原因 | 待测 |
| C1 | 具身角色在相同能力下增加状态理解、相处或审美价值 | 可比原型、主观体验、任务结果和持续选择 | 待测 |
| C2 | 同一身份融合两类能力，优于分别使用它们 | 同一用户的共同收益、干扰、成本和后续选择 | 待测 |

## 2. 参与者筛选：不只招喜欢产品概念的人

建议覆盖：已有多任务／多 AI 使用经历的人、较多独立活动但 AI 使用不密集的人，以及有较稳定协作与交流的人。尽量纳入不同职业与 AI 经验，不把程序员或创作者等同于目标人群。

筛选问题：

1. 最近两周，你在哪些事情上使用了 AI？举最近一次具体例子。
2. 同时进行过哪些任务？其中哪些需要你回来检查或作决定？
3. 你通常如何知道事情完成了、失败了或需要你介入？
4. 你独立进行活动和与他人共同活动的情况分别怎样？
5. 遇到难题、想讨论或想分享进展时，通常会怎么做？
6. 是否用过语音助手、角色聊天、桌宠或数字人？喜欢或不喜欢的原因是什么？
7. 是否愿意用匿名编号记录活动事件，并在复盘时展示自行选定的例子？

保留不喜欢角色、没有协调问题和已有满意替代方案的回答。它们用于确认边界，不因“不符合预期”而从研究中删除。

## 3. 启动访谈：约 30～45 分钟

### 3.1 最近一件真实事情

- 最近一次借助 AI 完成的事情是什么？从开始到结束发生了什么？
- 哪些步骤由你完成，哪些交给 AI？交接发生在哪里？
- 什么时候最顺畅？什么时候停下来、返工或放弃？
- 如果可以，请展示你自行选定、已去掉敏感信息的过程或结果。
- 不用 AI 时会怎么做？现在少做了什么，又多做了什么？

### 3.2 协调与注意力

- 最近一次必须同时处理几个结果是什么时候？具体有几个？
- 哪条消息需要行动，哪条只是让你知道？如何判断？
- 中断后回来时，需要恢复哪些信息？大约花了多久？
- 目前如何排序、合并通知、安排检查时间？哪些做法已经有效？
- 如果没有额外工具，这些问题是否重要到值得改变习惯？为什么？

### 3.3 交流与支持

- 最近一次想找人讨论、倾听或分享进展是什么时候？
- 当时想得到什么回应？实际得到了什么？
- 现在和以前相比，哪些交流减少、增加或变好了？你如何判断与 AI 有关？
- 有没有独自做事但感觉很好、并不想交流的时候？
- 真人、社群、AI、娱乐或其他方式分别帮上了什么忙？有哪些不适合的时刻？

### 3.4 形态偏好放在访谈后半段

- 展示能力相同的文字、声音、非人形角色和人形角色概念；轮换展示顺序。
- 请参与者描述愿意使用和不愿使用的具体场景，不要求选出唯一赢家。
- 分别询问状态是否清楚、相处是否舒服、外观是否喜欢和是否打扰。
- “看起来可爱／专业”先记为第一印象，不当作长期收益或支付证据。

不要用“AI 会让你孤独吗”“你是否需要一个懂你的助手”作为开场问题。这些问法会把产品叙事带进回答。

## 4. 十四天事件记录模板

参与者使用匿名编号。只记录研究需要的事件元数据与自行提供的摘要，不默认采集完整屏幕、私聊或工作文件。

### 4.1 每次关键事件

| 字段 | 填写说明 |
|---|---|
| participant_id / event_id | 匿名参与者与事件编号 |
| 日期与情境 | 工作、学习、日常安排、休闲等；设备和地点只记必要类别 |
| 想完成什么 | 用自己的话写目标 |
| 模式 | 人为主、与 AI 配合、AI 执行后核验、其他 |
| 同时等待的任务 | 实际数量；不知道就写未知 |
| 触发 | 主动查看、通知、异常、需要选择、主动交流等 |
| 做了什么 | 阅读、切换、补充说明、核验、纠错、交流或其他 |
| 人的处理时间 | 实测或估计分钟；明确标记两者 |
| 恢复上下文时间 | 若发生中断，重回任务大约花多久；无中断记不适用 |
| 结果 | 完成、继续、失败、放弃、未核验；不强行二分成功失败 |
| 费力度 | 自定义 0～10 事件评分；不是经验证的心理量表 |
| 交流需要 | 当时是否想获得回应，想得到哪一类回应 |
| 实际支持 | 来自哪里，是否满足；没有需要与有需要但无人回应分开 |
| 当前应对 | 已用过哪些功能或习惯，是否有效 |
| 其他因素 | 截止时间、工作量、设备故障、社交机会等 |

### 4.2 每天简短结束记录

- 今天是否有需要记录的事件？没有、忘记记录、没有使用 AI 分开填写。
- 今天整体更轻松、差不多还是更费力？最主要原因是什么？
- 今天是否有想交流而没有得到合适回应的时刻？也记录交流很充分的情况。
- 今天是否主动减少任务、关闭通知、寻求他人或选择独处？结果怎样？

研究提醒产生的使用或交流单独标记，避免当作自然需求。无需为了凑记录主动使用 AI、制造多任务或减少真人交流。

## 5. 结束复盘与证据汇总

逐人选择两三个真实事件回看，并询问：这件事是否具有重复性、目前代价是否值得解决、已有方法为什么不够、什么变化能带来实际帮助。

| 汇总项 | 口径 |
|---|---|
| 参与者去向 | 招募、开始、完成、退出、缺失分别计数 |
| 有效记录天数 | 明确区分无事件与未记录 |
| 协调时间 | 按人报告实测与估计值；不把整个 AI 运行时间算成人力 |
| 任务机会与错误 | 需要核验的次数、实际核验、遗漏与返工分别报告 |
| 支持缺口 | 有交流意愿且现有回应不足的事件；独处时长不是替代指标 |
| 共现 | 同一人是否重复出现两类问题，是否在同一活动里发生 |
| 替代方案 | 已解决、部分解决、未解决，以及替代所需的时间与费用 |
| 反例 | AI 减负、交流改善、不需要角色、简单设置已解决等 |

这轮样本用于描述机制和选择下一步。不以“多数访谈者说喜欢”推算总体需求；同一个人十次事件也不是十个独立用户。

## 6. 比较试验卡 A：协调能力与形态分开

**待测问题**：协调方式是否减少净负担，具身表达是否提供额外收益？

| 项目 | 试验设计草案 |
|---|---|
| 对照 0 | 用户合理配置过的现有工具；不能故意制造难用基线 |
| 对照 1 | 结构化任务队列、关键事项与汇总，先不加入额外智能推断 |
| 方案 2 | 相同界面加入 AI 协调，明确新增决策或过滤能力 |
| 方案 3 | 与方案 2 相同内容和能力，增加角色状态表达 |
| 任务材料 | 等难度的多任务场景，预先定义完成标准、关键异常与合理决定 |
| 控制 | 任务与顺序平衡；相同输出质量、等待时间与帮助强度，差异逐项记录 |
| 主要结果 | 达到既定质量的总人力时间、关键遗漏、决定质量 |
| 辅助结果 | 费力度、恢复上下文、打扰、掌控与偏好 |
| 成本 | 新增助手推理、配置、解释、人工救援与纠错全部计入 |

可先分两步比较对照 0／1 与方案 2，确认协调价值后再比较形态，避免小样本被分成过多条件。早期如使用预设事件，必须标为模拟；后续补真实 Agent 运行验证。

探索样本先估计波动和用户认可的最小收益，再锁定正式门槛与样本量。预先定义关键错误；样本未出现错误只能说明本轮未观察到，不等于零风险。

**反证**：结构化队列已解决问题，额外 AI 没有可观察增益；或者看起来省时，却增加了关键遗漏、核查或用户误解。此时应收缩额外 AI 层，而不是用满意度掩盖质量。

## 7. 比较试验卡 B：伙伴的持续相处价值

**待测问题**：稳定伙伴是否在重复活动中提供具体价值，形态与用户情境如何匹配？

- 首先选定确有相关需求且自愿参与的人群，记录基线、正常真人交流与现有工具。
- 先比较普通助手与具有稳定互动方式和共同活动的伙伴；若要归因于形态，再比较同能力的非人形、人形和无身体表达版本。
- 保留日常活动或真实可得的同行交流作为替代比较，明确各自可得性与时间成本。
- 观察互动当下、次日未互动时、研究末期三个时间点；不能只测聊完之后。
- 记录自愿回来、具体有价值事件、主动关闭、打扰、退出、现实支持变化，以及是否感到不得不持续使用。
- 不用更会迎合、更多提醒或更高模型质量的实验组，去宣称外观本身有效。

四周仅为探索起点；正式结果比较需要适当样本与分析计划。一般产品试验衡量体验和行为，若要宣称心理效果，应另行采用相应的研究设计，不能把自定义评分叫作临床证据。

**反证**：只增加时长、首日好奇和互动后短暂满意，持续选择或非使用时体验没有对应改善；或相处收益被打扰及其他负面体验抵消。结果应触发互动设计修订，不能直接转换成增长指标。

## 8. 比较试验卡 C：同一伙伴融合是否值得

只有在同一批用户确实存在两类需要时，再比较“分别使用协调工具与角色”以及“同一身份下连续相处与行动”。保持角色质量、工具能力和服务额度尽量一致。

观察同一活动中的上下文重复、跨模式切换、结果质量、相处体验和真实选择。不要只统计用户是否点过两个入口。

如果共同活动增强理解、减少重复且用户愿意继续，可以进入套餐交易验证；如果用户偏好分离，就保留分离。短期偏好不证明长期协同，也不证明该功能应独立收费。
