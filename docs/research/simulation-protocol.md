# AI 伙伴协调情境试测说明

> 2026 年 9 月 13 日。材料与工程验证阶段；没有新增真实用户证据。配套 [离线原型](../../prototypes/companion-validation/index.html) 与 [需求验证工作包](validation-kit.md)。

## 1. 这一步回答什么

文献已为“部分使用者存在协调负担”提供研究依据，但不能直接证明新的桌面伙伴能够减少负担。先把这个产品主张变成可观察的行为问题：看到同一组事实时，协调摘要能否帮助人更快作出正确决定？摘要出错时，人能否识别并纠正？

这是交互材料试测，不能验证真实模型能力、自然需求频率、市场规模、付费意愿或长期情感支持。用户原始假设中的“没有助手就会被信息压垮”和“情感支持替代组织交流”仍不能作为已确认事实。

## 2. 如何运行

在 Windows 中打开仓库的 [prototypes/companion-validation/index.html](../../prototypes/companion-validation/index.html)，用现代浏览器运行即可。无需安装或启动服务。所有素材、样式与逻辑在同一个文件中，没有网络请求。

阅读说明、自愿开始后，完成两轮情境和每轮体验记录。结束页展示判定依据，可以下载本次 JSON。页面没有自动保存，刷新或关闭前应自行决定是否导出。不要填写姓名、工作秘密或其他隐私。

首次可由研究负责人检查材料是否好懂；研究负责人和开发者的操作必须标为试运行，不能混入参与者数据。已读答案或做过一遍的人不再作为首次接触样本。

## 3. 材料设计与控制

| 维度 | 当前实现 | 局限 |
|---|---|---|
| 场景 | 课程上线、工作坊筹备；每个包含三个待处理事项 | 结构近似但未通过预试证明等难；均以确认条件为主，代表性有限 |
| 基线 | 已结构化的任务队列、简述、可展开原始证据 | 不是用户自己的全部工具；不能代替与优化后实际流程比较 |
| 协调条件 | 相同队列上方增加一段协调摘要 | 原始证据仍可查；差异包括摘要内容、页面占用与阅读量 |
| 摘要质量 | 每次页面加载独立随机分配准确版或遗漏版 | 研究人为设定的两类材料，不代表真实错误率；实际招募小样本可能不平衡 |
| 遗漏版本 | 两项过早对外操作建议，遗漏必要确认 | 只覆盖一种错误机制，不代表所有助手失误 |
| 顺序 | 四种情境与模式顺序，默认随机；研究者可手动选择 | 手动分配会记录；四种顺序与两类质量形成八种组合，随机不保证人数均衡 |
| 反馈 | 两轮完成后才展示答案 | 仍可能存在跨轮学习，不能认定已消除 |
| 形态 | 两轮结束后，独立切换静态抽象角色与文字状态 | 不计时评分；只供讨论，不是具身角色效果实验 |

每位参与者只接触一个摘要质量版本。质量是参与者之间的条件，模式是参与者内的条件。准确与遗漏版本必须分开报告，不能将人为设置的比例解释成真实产品平均收益。

当前版本适合少量认知访谈和材料预试。正式效果试验需在预试后锁定分配、样本量、最小有意义差异和分析方法。不能凭两轮时间之差作显著性或普遍效果判断。

## 4. 数据字典与解释

| 字段 | 解释 |
|---|---|
| `kind`、`version` | 明示预写模拟及版本 |
| `sessionId` | 本次页面生成的随机标识，不是稳定用户 ID；不能靠它统计独立用户数 |
| `sequence`、`assignment` | 四种顺序之一，以及随机或手动选择 |
| `summaryQuality` | 本次被分配的准确或遗漏版本；未进入摘要轮也可能有这个分配值 |
| `trials[].scenario`、`mode`、`order` | 情境、展示方式、轮次 |
| `wallMs` | 进入情境到提交或退出的总经过时间 |
| `visibleMs`、`hiddenCount` | 页面可见时间与转为隐藏次数；不等于实际注意力、认知努力或任务切换次数 |
| `events` | 证据展开/收起、选择变化、页面可见性事件；不证明用户认真阅读 |
| `answers`、`status` | 最终选择及提交/放弃；中途退出不补造答案，不计作全部做错 |
| `score.correct` | 三项中符合材料规则的决定数 |
| `score.criticalErrors` | 两个关键确认事项中错误决定的数量，含危险放行或过度取消 |
| `score.unsafeActions` | 未满足条件即公开、发送或付款的模拟选择数 |
| `score.unnecessaryStops` | 不必要暂停或取消数；与关键错误可能重叠，不能相加当总错误数 |
| `effort` | 0～10 自定义费力度，0 是有效回答；空值代表未填写 |
| `difficulty` | 可选简短反馈，未经验证的自述 |
| `preview` | 角色预览切换记录，不能等同角色偏好或价值 |
| `endedReason` | 完成或参与者主动退出；直接关页的情况无法自动保留 |

体验填表时间不在决定耗时内。这次没有测量真实 AI 配置、推理延迟、纠错成本、订阅费用或长期使用，不能称为产品“净人力收益”。

## 5. 主持方式与下一步

1. 先检查参与者是否理解任务和选项。若要边做边说，应将这些场次标为认知访谈，不与安静计时场次混合。
2. 正式计时期间不提示答案。任何解释、技术故障与外部中断由研究者单独记录；页面未自动记录研究者帮助。
3. 两轮结束后询问：用了哪些证据、何时信任摘要、何处多做了核验、自己的实际工作中是否出现类似情境。允许回答“没有”。
4. 展示两种状态表达，请其描述理解、审美、打扰和希望如何互动。不要把静态形象选择当成长周期数字人需求。
5. 按人汇总，并单独列出退出、缺失、版本、顺序和帮助情况。准确摘要与遗漏摘要分开看；不能为了追求平均省时排除错误或慢用户。

若准确摘要仍未显示可观察收益，先检查基线是否已足够、摘要是否重复、场景是否过于简单。若省时伴随危险放行增加，应调整证据呈现与核验机制。如果结构化队列已足够，应保留这一结果，而非为了 AI 伙伴概念继续增加智能层。

真实需求还需按工作包进行 14 天事件记录。情感支持、角色持续价值和两类需求融合分别使用试验卡 B、C；本原型没有替它们作出结论。

## 6. 工程检查与研究状态

运行 `npm run verify:prototype` 可检查两类摘要、四种顺序、完整两轮流程、判定、可见性计时、退出、导出数据结构及角色切换。脚本只使用模拟 DOM 和程序化输入，不生成参与者记录。

当前环境没有可用的浏览器控制实例，因此尚未完成真实浏览器中的视觉、原生必填校验及文件下载验收。脚本通过不等于浏览器验收，更不等于用户研究完成。首次人工预试需补充这些检查。

本轮交付完成的是研究材料。参与者、自然任务记录、实测结果、真实支付与统计结论均未产生。
