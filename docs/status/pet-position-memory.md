# 位置记忆与下一增量

日期：2026-09-14。分支：`feat/pet-position-memory`，基于尚未合并的透明角色分支。对应T02/T06的部分实现，不等于完整工作包或阶段门通过。

## 本轮完成

角色窗口位置保存在本机应用数据目录的 `desktop-settings.db`，与待办数据库分开。拖动停止至少400ms后，由250ms周期的后台线程保存，避免每个移动事件写盘。正常退出会补存待写位置；强制终止时，尚未到保存时机的最后移动可能丢失。

启动读取上次物理坐标，再按当前可用显示器的工作区修正；第一次启动使用主屏右下角。托盘“找回角色”改变位置后也走同一保存逻辑。偏好数据库异常或来自新版本时保留原文件、记录诊断并使用默认位置，不阻止角色和已有待办功能启动；本轮没有增加可视化设置错误提示。该数据属于桌面宿主，不向前端开放路径或SQL。

## 下一轮：真实文字对话

用户结果：点击桌面角色，输入一句话，看到真实模型的回复；等待时能停止，失败后能重试。保留“记待办”的明确入口，区分对话与任务保存。

准入条件：

- 明确内部演示使用的模型服务、模型名、调用方式与测试额度；密钥通过本机安全配置或服务端提供，不通过聊天发送，也不进入前端产物。
- 固定会话ID、请求ID、消息和生成状态契约，以及超时、取消和迟到结果处理规则。
- 区分单机内部模型验证与正式云端多用户T09。后者仍保留T41/T42身份隔离和服务端凭据前置，不能用本地样机替代通过。

准出条件：

- 至少一条真实模型交互贯穿角色输入、服务请求、流式文本和结束状态；模拟适配测试不算真实调用验收。
- 角色状态由请求驱动：待机、生成中、已停止、失败；不宣称“已倾听”或“已办完”尚未发生的事情。
- 停止后不追加旧文本，旧请求不覆盖新会话；断网、无效配置、超时和服务端错误可见且可恢复。
- 凭据不出现在前端、仓库和普通日志中；输入/输出长度、并发和超时有限制。
- 记录真实请求的延迟与可取得的用量；服务未返回用量时明确未知，不编造成本。
- 更新可复现运行说明、自动化测试与真实调用结果；无可用模型或凭据时仅交付适配基础，不标记对话能力已通过。

后续顺序：文字对话闭环 → 可查看/删除的会话记录 → 有来源的偏好记忆 → 有授权范围和结果核验的有限任务。语音、手机接续与硬件继续按依赖进入后续增量。
