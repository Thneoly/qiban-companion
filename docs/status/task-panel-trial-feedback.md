# 任务面板试用反馈三条：交付记录

> 2026 年 10 月 30 日。试用反馈消化（挂账见[交付待办](../planning/delivery-backlog.md)「待办面板体验」节，Multica TUWE-3，PR #84）：本地待办面板从 30 行极简实现补齐删除、终态折叠与状态筛选。范围仅本地任务（companion.db / TaskPanel）；不改任务事实链路、不改聊天记录链路。

## 实现与归属

- **删除（IPC）**：`TaskStore::delete` 只 `DELETE` companion.db `tasks` 表的指定行，删空返回 `NotFound`。**无 schema 迁移**（`user_version` 保持 1）：任务事实沉淀在 chat-history.db（HistoryStore，以执行指纹为键），聊天记录是独立库，与 `tasks` 行无外键或数据关联。新命令 `delete_task` 三处注册齐全（`build.rs` 命令清单、`capabilities/main.json` 白名单、`invoke_handler`），`permissions/autogenerated/delete_task.toml` 由构建生成入库。
- **删除边界文案**：前端删除前 `window.confirm`：「仅从这台设备的待办列表移除「标题」？任务事实沉淀与聊天记录不受影响。」
- **终态折叠**：终态 = 已完成/已取消/失败，默认折叠为一条计数行「展开已结束的 N 条」，点击展开/收起；不做分页。`unknown`（结果未知）不归入终态——可能仍需核对，保持可见。
- **状态筛选**：待办（queued）/ 进行中（waiting_authorization、running、verifying、cancel_requested、unknown）/ 已结束（终态）三档快捷切换，默认「待办+进行中」；「已结束」档与折叠计数行同状态、双入口。空筛选显示提示；无终态时该档禁用。纯前端，不加 IPC。
- **契约**：`CompanionClient` 新增 `deleteTask(id)`（无返回体）；浏览器 preview 客户端同语义镜像（删内存行、缺失抛「未找到任务」）。

## 共享待办与执行任务列表的对齐判断

- **账号侧共享待办（AccountPanel）：不对齐。** 数据归协调器服务端（HTTP 轮询同步），删除需新增服务端 API，且手机 Web 显示同一列表、两端一致性优先；该列表实际只出现 queued/cancelled 两态，三档筛选退化。超出「删除只动本机任务行」的边界。若试用反馈再指向它，另立任务（coordinator 与手机端一起改）。
- **执行任务列表（ExecutionPanel）：不对齐。** 它是任务选择器（点击查看执行详情），容量上限 100；completed 正是「读取已保存草稿」的回访入口，默认折叠会挡住该路径；无对应试用反馈。维持现状。

## 边界

- 删除是不可恢复的本机列表行移除（无软删/回收站）；取消→删除是明确的两步操作。
- 待办完成/失败路径尚未在本地面板出现（本地任务只有 queued→cancelled），删除按钮按「终态」语义统一实现，完成路径上线后无需再改交互。
