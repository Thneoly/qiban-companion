# T04：可运行的语音链验证入口

日期：2026-09-16～17。分支：`feat/voice-chain-spike`，从已合并的main `13d4982`开始；先前PR #1～#7均已合并，PR #1待办刷新评审已修复并关闭。合并后main的Windows CI运行`35089541700`已成功；这不代表本分支的外部CI结果。

## 用户可操作的范围

桌宠 → 任务面板 → “语音实验” → 打开语音实验。分别填写语音API基地址、识别模型、合成模型和音色编码，或者显式点击“填入智谱语音示例”。语音地址初始为空，避免误用文字专用地址；“设置语音密钥”在Windows原生密码窗口为该地址保存凭据，React看不到密钥。文字地址、模型及原有密钥保持原配置，例如`glm-5.3-flash`。语音非密钥参数仅保留在当前实验界面，暂不持久化；系统密钥可在Windows凭据管理器移除。

点击“录制语音”才申请麦克风，最多录制10秒，也可提前结束。或者选择30秒以内的测试WAV。准备音频不会上传；点击“运行并播放”后才依次识别、生成简短回复、合成、播放。停止、关闭实验或窗口失焦会释放音轨/播放资源并请求取消在途网络；迟到结果不会重新播放。系统授权迟到时同样释放返回的音轨。

结果显示识别文本、回复、各网络阶段耗时、提交至播放开始时间、输入/输出时长及文本用量。播放状态依据媒体事件，合成成功不算播放成功。语音费用未返回时保持未知，不能按0计算。

## 实现与配置边界

- 使用兼容`/audio/transcriptions`的multipart上传和`/audio/speech`的JSON/WAV协议；ASR、TTS、音色编码可编辑。语音服务可与文字服务采用不同地址和凭据；ASR/TTS仍共享同一语音地址。智谱仅为按钮预设，不支持所有厂商的专有协议。
- Rust从保存配置取得文字地址，并核对与打开实验时展示的地址一致；语音地址单独通过同一HTTPS/本机地址校验。文字和语音密钥分别按规范化地址从Windows凭据管理器读取，不自动跨地址复用，不进入前端、文件或日志。禁止HTTP重定向；网络错误只返回受控提示与HTTP状态。
- 录音在前端解码为16 kHz单声道PCM16 WAV。Rust再次校验RIFF结构、长度、PCM参数及最长30秒输入/60秒输出；最大8 MiB，文本回复最多500字。单个语音探测并发1、网络链总时限120秒；没有自动重试或持续监听。
- 只在main辅助面板授予语音命令权限，桌宠窗口未获得新命令权限。CSP仅新增本地blob媒体播放，不开放前端外网请求。增加reqwest multipart及其锁定依赖。
- 三个阶段使用本轮冻结的文字与语音配置；复用文本流解析器，但不读取或写入桌宠聊天历史。语音与桌宠聊天各自有并发边界，目前不是产品级全局额度账本。
- 本轮先测串行、非流式语音基线，未实现分句TTS、音频时钟口型、桌宠语音状态、回声处理或实时双向语音；这些仍属T11/T12后续工作。

## 决策、准出与下一步

**当前结论：T04的本机链路已具备验证条件，T04全链真实服务与成本准出未通过。** 不把样机或本地模拟性能写成G1/G2通过。

1. 在语音实验里选择正确的通用语音地址并配置其凭据，确认开通、可用额度和限流条件，或选择同协议的其他服务；不要求用户在对话中发送Key。用户确认后再发起下一次真实测试，保留现有Coding文字服务配置。
2. 完成真实ASR→现有文字模型→TTS→播放，核对供应商账单；用真实设备补麦克风拒绝/恢复、噪声与回声用例。
3. 根据实测决定流式ASR/分句TTS路线，再推进T11/T12；T06/T10记录恢复与T13/T14有限记忆仍按[交付计划](../planning/delivery-backlog.md)接续。

协议依据：[智谱ASR文档](https://docs.bigmodel.cn/cn/guide/models/sound-and-video/glm-asr-2512)规定WAV/MP3与30秒输入限制；[TTS接口](https://docs.bigmodel.cn/api-reference/模型-api/文本转语音)提供模型、音色和WAV格式参数。本轮只采用这些协议事实，不采用宣传中的识别率作为本项目证据。[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)说明安全上下文、授权及迟迟不返回的可能性，对应实现中的显式启动和迟到释放逻辑。

接续（2026-10-07）：真实云端全链、麦克风权限、停止与账单已在智谱验证，期间发现并修复智谱WAV头RIFF size兼容缺陷，见[真实语音全链记录](voice-real-chain.md)。本文的429教训与地址/密钥拆分设计继续有效。
