# 可配置模型输出预算

日期：2026-09-15～16。分支：`feat/model-output-budget`，基于对话阅读增量。

## 配置方式与行为

角色气泡 → 模型设置 → “最大输出 tokens” → 保存。允许128～8192的整数，默认1024。气泡会显示已保存的上限，重新打开气泡可刷新显示。正在进行的请求使用发起时的配置快照，设置只影响后续请求；只修改预算不会清空前文或改变模型/密钥。

该数值通过现有Chat Completions协议的 `max_tokens` 发送；服务商仍可能拒绝参数或要求更小上限，不代表所有协议通用。没有自动提高预算、自动重试，也未加入厂商专属思考参数。智谱文档将此参数说明为请求的输出上限，达到上限可能截断；模型自身的限制另行存在，参见[官方核心参数说明](https://docs.bigmodel.cn/cn/guide/start/concept-param)。

上限不是实际用量，不等于字数或费用金额；设置更高值不保证更快或一定完整。90秒总超时、64 KiB文本上限和4 MiB响应上限仍保留，不能通过提高tokens绕过。前文仍受6轮/合计12000个Unicode字符限制，与输出预算分开；超过前文容量的完整问答可能不再保留，不能把高输出预算当作长期记忆。

旧配置没有该字段时按1024读取，不重写旧数据、不覆盖地址/模型；用户保存后才写入新增字段。非法值由界面和Rust分别拒绝，不覆盖已保存配置。密钥存储方式不变。

模型返回 `finish_reason=length` 时显示“回复达到长度限制（本次上限…tokens）”，引导缩短问题或到模型设置调整；仍作为未完成回复，不加入前文。这个提示不宣称截断一定只由本地预算导致，服务商自身限制也可能生效。

## 原生客户端真实调用

在Windows客户端中通过设置界面将输出上限临时设为4096，沿用本机已配置的 `glm-5.3-flash` 和凭据。发送“请给出6条桌面工作时的小休息建议，每条约30字，不要标题。”后，13.05秒完成回复，服务商返回用量478 tokens，回复222个字符；界面显示“已完成”，完整问答进入临时会话。

验证后已恢复原来的1024上限并清空测试会话，模型和密钥未修改。此结果仅证明配置、请求和回复显示链路可用：本次实际用量低于1024，不能据此证明提高上限必然解决此前的截断，也不代表稳定延迟或质量评估。
