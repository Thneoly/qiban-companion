## 设计审视结论

| 发现的缺口 | 本轮处理 |
|---|---|
| 聊天记录不能自动等同已确认事实 | 首增量只有用户手动保存；不自动扫描历史 |
| 任务事实尚无可信执行源 | 明确结构与依赖，禁止当前创建；留给T16真实事件 |
| 跨模型默认携带会产生用户未预期的数据发送 | 库共享，许可按地址＋模型分开，默认关闭 |
| 只删卡片仍可能从聊天复述旧信息 | 更正/删除/收回使用时，同事务清空所有模型聊天；UI事前说明 |
| 修改已选正文会突破上下文限额 | 核对所有引用策略，超过800字整次拒绝，原数据不变 |
| 单独memory.db难与聊天原子删除 | 在chat-history.db设计v2迁移，既有问答保留 |
| 多窗口/进程或迟到回复让删除失效 | IPC期望版本、协调epoch、后端失效回写；单实例是写入开放前置 |
| 通知失败可能诱导重复删除 | 区分已提交与待刷新，旧窗口发送前重新核对 |
| 删除标记被误说成已做同步 | 本地只保留无正文标记，跨端20例仍待T23/G3 |

30条/200字/5条/800字是开发设计初值，不是用户研究结论。更正时重开全部聊天的取舍需要体验验证；文档形成不表示PO已批准、人日已确认或G2已通过。原计划T13/T14各2～4人日须按单实例、导出和并发协调重新估算，未把新增复杂度藏在既有承诺里。
