# T06/T10：本机对话保存、恢复与删除

日期：2026-09-17。分支：`feat/chat-history-persistence`，接续语音实验分支。本轮只交付本机文字记录闭环，未完成整个T06/T10或G2。

## 用户结果与保留规则

桌宠 → 聊一聊。完整问答自动保存；退出程序再启动后，打开气泡会显示“已恢复本机记录”，可从“最近 N 轮”或“展开阅读”查看。发送下一条时带上当前服务地址及模型的已保存前文；读取记录不依赖服务商在线。

- 所有地址和模型合计最多6轮、12000个Unicode字符；一轮包括问题与回答，按完整问答完成顺序淘汰最旧记录。没有按天保留或无限归档。
- 地址与模型共同决定上下文范围。切换后不会发送其他范围的记录，切回可恢复尚未被全局容量淘汰的问答。只改输出预算不会隔离记录。
- 只保存正常完成的问答；停止、断线、超时及截断片段不保存。单轮超过12000字时不保存该轮，并保留原有记录。
- “清空对话”删除本机所有地址/模型的记录，同时清除当前气泡内容；即使当前模型没有记录也可操作。生成未结束时须先停止。删除失败保留原记录并提示，不虚报成功；删除后重启不会恢复。
- 记录在本机明文保存，界面显示此边界。删除不撤回已发送给服务商的内容，也不清除系统备份；没有承诺磁盘取证级擦除。API Key仍仅在系统凭据管理器中。

## 数据与失败处理

纯会话领域逻辑从宿主迁入`crates/companion-core/src/conversation.rs`；SQLite访问位于`crates/companion-storage/src/history.rs`。Tauri负责配置、窗口、取消和组装，前端不能传数据库路径、SQL或自定义历史。

系统应用数据目录新增独立`chat-history.db`，首次运行以事务从版本0创建版本1的`chat_turns`表。列为递增ID、服务地址、模型、问题、回答；不改变待办与模型设置数据库，也不会把旧版仅在内存中的会话伪装成迁移成功。未知新版或损坏结构拒绝打开，原文件不覆盖；应用仍可启动，聊天入口提示记录不可用，需要检查目录或更新客户端后重启。

追加及全局容量淘汰在一个SQLite事务中提交，再更新内存；开启secure_delete，清空成功后才更新界面。完成结果新增`historySaved`：保存失败时回复仍显示“已完成”，同时提示未保存、不会恢复或加入前文；不自动重复调用模型。旧响应缺少字段按未确认保存处理，IPC v1保守兼容，不把旧内存会话当成落盘。

模型选择与开始请求遵守设置→会话的锁顺序；会话版本使模型切走再切回、删除后的迟到完成失效。关闭气泡沿用原有取消机制。语音实验不读写此记录，不新增长期记忆、摘要、向量检索或任务执行。

## 实际验证

| 检查 | 结果 |
|---|---|
| 前端 | 类型检查、10项单元测试及生产构建通过；解码器拒绝错误保存状态，旧响应保守视为未保存 |
| 浏览器 | 18项通过，含恢复提示、删除失败保留记录、成功删除后重开为空、完整但未保存的回复不混入历史，及既有文字/语音/Live2D回归 |
| Rust | 26项通过、1项系统凭据集成忽略；格式与Clippy通过 |
| 存储/状态 | 数据库关闭重开、地址/模型隔离、跨范围容量淘汰、超长问答拒绝、删除幂等、写入失败保留旧记录、未来/损坏结构拒绝、删除/切换后的迟到写回拒绝 |
| Windows release | 构建通过，原生WebView2中完成保存→退出进程→重启恢复→携带恢复前文发出下一请求→清空→再次重启为空 |

原生测试开始前确认本机不存在该新数据库，只有测试自建记录；使用无密钥本地HTTP夹具，共2次模拟模型请求，没有调用付费服务或读取密钥。测试结束恢复原文字配置，清除测试记录。结果在忽略目录`.cache/history-native-result.json`、`.cache/history-restored.png`，本机助手`.cache/history-native.cjs`会拒绝在已有记录库上运行。截图检查恢复后的阅读视图和保留说明可见。
