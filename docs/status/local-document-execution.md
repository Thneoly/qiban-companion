# T16 本地执行台账与文档摘录

2026-09-21。接续[手机同伴接续设计](../architecture/device-continuity.md)，交付 T16 的受限本地子项及 T17/T18b/T19 的最小验证场景。尚不是手机控制、通用 Agent 或 T16 全包准出。

## 可实际使用

角色气泡 → 任务面板 → 左侧“文档任务” → “打开文档任务”。选择 UTF-8 `.txt`/`.md`（最多 256 KiB），生成摘录预览，再明确点击“确认保存草稿”。固定取前 8 个非空行，每行最多 240 个 Unicode 字符；这是原文摘录，不宣称语义摘要，不调用模型、不使用记忆、不上传原文。

确认前可取消；确认后执行一个短小的文件保存动作，关闭面板不取消该动作。创建新文件而不覆盖已有内容，完成后“读取已保存草稿”实际读文件并验证内容，不将数据库里的预览冒充文件结果。普通待办仍只记录，不能通过任务标题执行命令或读取任意目录。浏览器预览明确提示仅桌面可执行。

输入文件由用户的文件选择控件授予读取，前端只提交文件名和有界文本；Rust再次验证格式、大小和控制字符。宿主不接收输出路径，产物固定在应用资料目录的 `document-drafts/<action_id>.md`。不保存完整源文件，只存摘录、源文件名、输入指纹与执行记录；均为本机明文。当前最多 100 条执行记录，尚无执行记录清理/产物导出功能。原文选择发生变化需新建任务。

## 实现与一致性

- `companion-core::execution` 定义任务、动作、尝试、事件和合法状态转换，负责纯摘录和 SHA-256 指纹。
- `companion-storage::execution` 拥有独立 `executions.db` schema v1，与已有待办/聊天/记忆库分离，不改变旧数据库版本。新库以事务建表，拒绝未来版本。
- 任务、动作、尝试、事件各自持久化；状态变化与事件在同一 SQLite 事务提交。`request_id` 唯一，绑定文件名及全文指纹；相同请求返回原任务，换内容拒绝复用请求标识。
- 确认比较任务 revision；不可变预览、产物名和 SHA-256 随动作持久化。原子记录批准版本、运行状态、attempt_id、执行者实例和 30 秒本机租约，再进入文件写入。
- 一个本机执行锁串行保存/核对，原有资料目录独占锁阻止另一进程处理同一数据库。当前租约仅用于本机发布前检查和重启失效；没有分布式抢占、续租或云端授权语义，不可直接开放为远程执行器。
- 先独占创建同目录暂存文件，写完并 sync，再用不覆盖目标的硬链接发布，最后清理自己创建的暂存文件。已有目标不覆盖；文件/目录链接与 Windows reparse point 拒绝使用。部署文件系统需支持硬链接，本机 Windows/NTFS 已验证。
- 完成后核对文件正文及哈希，再提交完成回执。回执提交失败保留 running；重启首先将旧 running 标为 unknown，再只核对已有文件，绝不自动再执行。

| 恢复时的证据 | 处理 |
|---|---|
| 已有产物，正文和哈希匹配 | 补记 completed，保持原 action/attempt |
| 最终产物不存在 | 标记 failed，未自动重试；可能保留中断的暂存文件 |
| 内容冲突、无权限或无法读取 | 保持 unknown，不覆盖、不称已完成 |
| 确认前已取消 | 保持 cancelled，拒绝旧确认 |
| 旧 attempt 回执 | 拒绝修改当前状态 |

运行中取消不被伪装成已取消。本轮只有一个短文件发布动作，UI仅在确认前提供取消；运行中/已完成收到取消命令会拒绝，用户核对实际产物。长任务的 cancel_requested、协作停止和补偿动作属于后续 T16/T44。产物完成后若被用户改动或删除，读回会报错；历史完成事件不被当成文件永远存在的保证。

新增命令仅授予 main：list、prepare、detail、confirm、cancel、reconcile、result；pet 窗口不能调用。沿用 IPC v2，增加独立执行 DTO 和运行时解码；runtime.executorAvailable=true 表示存在此受限执行器，不能解释为普通待办自动执行。
