## 11. 首轮可直接细化的验收例子

### T02：角色窗口可收起且不持续妨碍工作

- Given 已安装测试构建、角色显示在第二块不同缩放的屏幕；When 拖动角色、切换工作窗口并收起；Then 角色位置符合支持规则，收起后不挡住鼠标输入，工作窗口不会持续被抢焦点。
- Given 开启窗口穿透模式；When 用户希望重新交互；Then 能通过明确托盘或快捷入口恢复，不因穿透失去控制入口。
- Given 显示器拔出或电脑休眠恢复；When 角色重新出现；Then 角色回到可见区域，或者明确显示恢复入口，不把窗口永久留在不可见坐标。

S1产物允许列出尚未解决的平台差异，但必须有决定与下一步；商用门按Q1要求检查。

### T11/T12：打断语音不重播旧回答

- Given 回答A正在播放且有缓冲片段；When 用户停声或开始下一轮；Then 本地播放停止，旧生成ID的迟到片段不被播放。
- Given 停声时工具仍在执行；When 界面更新；Then 对话播放停止与任务执行状态分别呈现，不把停声当作工具已取消。
- Evidence：生成ID、事件时间、音频播放事件、实际听感复核；不只验证取消接口返回成功。

### T20：动作完成但回执丢失

- Given 创建草稿动作已经落盘但完成回执尚未到达；When 模拟断线并重连；Then 执行器先核对动作记录和产物，避免再次创建同样副作用。
- Given 外部动作无法查明结果；When 用户查看状态；Then 显示结果未知并提供核对办法，不自动重发或宣称完成。

### T31：重复支付回调

- Given 一笔交易已成功并更新额度；When 同一交易通知重复到达；Then 权益只记一次，账本保留可追踪处理结果。
- Given 收款状态不确定；When 服务恢复；Then 从可核对来源确认后更新，不同时给用户收费成功和支付失败的矛盾结果。
- 测试沙箱与真实小额交易的证据分别存放。真实收付款由具备明确权限的人执行，本计划不会自动触发交易。
