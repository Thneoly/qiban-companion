# T44/T21：配对与动作授权协议

2026-09-26。配套[手机接续总体设计](device-continuity.md)、[交付记录](../status/device-pairing.md)。本轮落地可操作的配对闭环及动作授权存储内核；动作 HTTP 接口、远程执行器与派发尚未开放。

## 信任与权限

账号认证、设备关系、单次动作授权分开检查。账号来自认证适配器，不能由请求填写 owner。设备 ID 由服务端生成，绑定账号与当前会话；设备名称由用户填写，不代表硬件证明。重新登录不会自动继承旧设备权限，需要重新配对。保留原有账号共享待办的语义：查看/记录待办不依赖配对，不会触发执行。

当前只有 `document_excerpt` 一种范围，不能通过请求扩大到命令执行、任意文件、聊天或记忆。配对本身不授予某个文件的访问权；未来本机执行适配器必须通过系统选取器选定实际资源、登记资源 ID/版本，再为具体动作申请确认。

## 配对流程

1. 已登录电脑请求 `POST /v1/pairings/offer`，提交 1～40 字设备名称。服务端生成随机 UUID v4 的 32 位十六进制配对码（122 位随机量），五分钟有效，并限制在当前会话绝对有效期内；同一电脑会话重新生成会使所有先前待确认码失效。
2. 同账号另一会话通过 `POST /v1/pairings/preview` 提交配对码。仅核对，不消费码；返回电脑标识、名称、固定范围及有效期。
3. 手机明确确认后调用 `POST /v1/pairings/accept`，提交配对码、刚核对的 pairingId 和手机名称。服务端事务中重验账号、发起端有效性、时间和状态；绑定控制端、递增授权版本、清除码摘要。相同会话、自身配对、跨账号、超时和重放均拒绝。
4. 两端通过 `GET /v1/pairings` 获取账号内关系及当前会话角色；任一已认证的同账号会话可管理并撤销遗失设备的关系。`POST /v1/pairings/{id}/revoke` 要求当前 revision，防止旧界面覆写新状态。

首次实现使用输入配对码，没有扫码、摄像头访问或含长期令牌的二维码。配对码仅在首次响应和当前界面内存中存在；数据库只存 SHA-256 摘要，消费、重新生成或撤销后清除摘要。列表不返回码/摘要或会话 ID。配对记录每账号最多 100 条，暂不自动压缩历史。

接受配对响应丢失后先刷新列表核对；已消费码不能重新提交“补一次”。只有列表证明确未建立关系时才生成新码。桌面/手机界面使用请求代际与卸载检查，退出、撤销或后续操作后，迟到读取不覆盖新状态。

## 单次动作授权内核

该部分位于 `companion-core` 契约与 `companion-storage`，仅供可信执行适配器调用；本轮无 HTTP 或 Tauri 入口，也没有文件副作用。

| 操作 | 允许的调用者 | 核对及结果 |
|---|---|---|
| 登记/更新资源 | 配对中的电脑会话 | 资源 UUID、严格递增版本、启用状态；更新使旧动作失效 |
| 准备动作 | 配对中的电脑会话 | actionId、resourceId、resourceVersion、规范化参数的 SHA-256 摘要、pairRevision、scope；有效期最多五分钟 |
| 明确确认 | 配对中的手机会话 | 与准备记录完整一致、配对和资源仍有效；待确认 → 已确认 |
| 动作准入 | 原电脑会话 | 再次核对账号/两端会话/关系/资源版本/摘要/有效期；已确认 → 已准入，只允许一次 |
| 撤销关系/更新资源 | 同账号管理会话 / 原电脑 | 尚未准入 → cancelled；已准入 → cancel_requested |

动作 ID 同账号唯一，不能通过修改参数重用。确认和准入不是执行回执；准入后响应丢失必须查询授权状态与本地执行台账，禁止直接重新准入或盲目执行。动作记录每账号最多 500 条，未实现归档。

所有核对和变更在 SQLite `BEGIN IMMEDIATE` 事务中，撤销与准入存在明确提交顺序：撤销先发生则拒绝准入；准入先发生则记录请求停止。`cancel_requested` 不代表副作用已停止或回滚。实际执行器的停止、产物核对和完成回执是后续门禁。

## 会话与数据迁移

每次操作重验本机会话；配对双方检查服务端撤销、绝对过期和自有会话的 30 分钟空闲过期。伙伴身份可在重新登录后保持一致，配对权限不自动恢复。失效关系在查询时呈现 expired；后续准入始终重新检查，不能信任上一次列表。

协调数据库从 schema 2 迁到 3，新增设备、配对、资源版本和动作授权表；已有账号、伙伴、会话和共享待办保留。桌面本地数据库不参与迁移。启动旧 schema 2 程序读取升级后的库会拒绝，不可手改 user_version 降级。

当前手机 BFF 只开放列表、核对、确认、撤销路由；不开放生成码、动作准入和执行路由。Rust 桌面仅访问回环协调 API，Tauri 权限只授予主面板。仍需后续正式 HTTPS 部署、稳定设备密钥、在线能力与事件流设计。

## 准入与准出门禁

| 门 | 当前证据 / 后续要求 |
|---|---|
| 本增量准入 | 既有邮箱认证、安全会话与共享待办；用户明确要求推进 T44/T21，继续保留原生人工验收待补项 |
| 配对子项工程准出 | 一次性/期限/同账号另一会话、撤销/重开、跨账号拒绝、真实 HTTP + 手机页面组合、桌面 UI 回归 |
| 授权内核工程准出 | 单次准入、篡改/旧确认拒绝、资源变更、撤销竞争、迁移保留数据 |
| T44/T21 全包准出 | 真实 Tauri 窗口 + 手机人工闭环、设备能力/在线状态、执行器动作前核对、断线恢复、在途停止与回执核对；尚未满足 |
| T22 执行入口准入 | 先补上述执行适配器与确认界面，验证无权限无副作用、重复/迟到消息和结果未知；不可把普通待办自动映射成执行 |

后续首场景仍限定为用户本机选定的 UTF-8 文档摘录，资源与输出目录必须由电脑确认，手机核对具体预览后才准入保存。暂不接入任意 shell、目录长期权限、记忆同步或模型自动决定授权。
